# Local LLM + Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One setting (`llm.provider: api | local`) drives every LLM step; `local` runs a small GGUF model through llama.cpp `llama-server` on 127.0.0.1, started only for the LLM part of a stage; `run.py llmbench` compares small models (and the API) on the same prompts.

**Architecture:** New `llmconf.py` resolves the provider from `config/settings.yaml` (+ `.env` key) into base URL, model, key, budget and extra request fields, and owns `local_server()`. Our own call sites (`cveinfo/llm.py`, `mitigate/guide.py`) use it directly. iEXAM code (in-process `llm_service.py` and subprocess `build_api.py`) gets the same values through environment variables that `llmconf.export_env()` sets, so subprocesses inherit them. New `llmbench.py` builds fixed prompts from one run and records timings, RAM and validity.

**Tech Stack:** Python 3 stdlib (`subprocess`, `urllib`, `contextlib`), `requests` and `openai` (both already in `.venv`), PyYAML (already used), llama.cpp built from source (C++, CPU only).

**Spec:** `phases/phase-8c.md`

## Global Constraints

- No new Python dependency. llama.cpp is a native tool built for aarch64; `tools/` and `models/` are git-ignored.
- `llama-server` binds `127.0.0.1` only. It is started only inside `local_server()` and always stopped on exit (terminate, kill after 10 s).
- Secrets only in `.env`; never written to settings, logs, `llmbench` JSON or `guide.json`.
- `provider: api` must behave exactly as today; `LLM_BASE_URL` / `LLM_MODEL` env variables still override the `api` entries.
- Budgets, verbatim from the spec — api: `{context: 32768, max_tokens: 4096, page_chars: 4000, pages_total_chars: 32000, cve_batch: 8, timeout: 120}`; local: `{context: 4096, max_tokens: 512, page_chars: 1500, pages_total_chars: 6000, cve_batch: 2, timeout: 600}`.
- Local server: `port: 8091`, `threads: 4`, health wait 120 s.
- Tests: `.venv/bin/python -m unittest discover -s tests -t .`; no network, no real model in tests.
- Project is not a git repo: no commit steps.

## Review Focus

- `.env` still sets `LLM_BASE_URL` to NVIDIA while `provider: local`: local must win, or scan data leaves the machine (test in Task 1).
- Port 8091 already taken (a previous server left running): `local_server()` must fail clearly, not talk to a stranger's server as if it were ours (test in Task 2: health must come from the process we started — check the process is alive while polling).
- The model process dies mid-stage (OOM on the Pi): the stage's existing per-item error handling records a note and continues; the server is still cleaned up (test in Task 2).
- A stage interrupted by Ctrl-C or job failure: no orphan `llama-server` left holding ~400 MB (test in Task 2: exception inside the `with` stops the process).
- Qwen3 emits `<think>` despite `enable_thinking: false`: existing `extract_json` strips it; plan explanation text strips it too (test in Task 3).

## Rulings carried from the spec

- **Task 3 of the spec (`build_api.py`)** is not called anywhere in our pipeline (Metric 1 explanation scripts and top-K explanations are not run by `mitigate` or `attackplan`). It gets the provider switch through `export_env()`, but the benchmark covers tasks 1, 2 and 4 only. Cost if wrong: one more bench task later.
- **Server log:** written to `<run_dir>/llm-server.log` (append) instead of `pipeline.log`, so llama.cpp's verbose output does not bury the stage log; the last 20 lines are copied into the stage error on failure. Cost if wrong: one path change.
- **Gate "no request leaves 127.0.0.1"** is checked by running the stages with `NVIDIA_API_KEY`, `OPENAI_API_KEY` and `LLM_API_KEY` set empty and `LLM_BASE_URL` set to the NVIDIA URL: LLM output must still appear, and `llm-server.log` must show the requests.

### Task 2: `local_server()`

**Files:**
- Modify: `llmconf.py`
- Test: `tests/test_llmconf.py`, fake server `tests/fake_llama_server.py`

**Interfaces:**
- Consumes: `settings()` (Task 1).
- Produces: `local_server(s: dict, log_path: Path, command: list[str] | None = None) -> ContextManager[dict]` — no-op yielding `{}` for api; for local starts `[server, "-m", file, "--host", "127.0.0.1", "--port", port, "-c", context, "-t", threads]` (or `command` in tests), stdout+stderr appended to `log_path`, polls `GET http://127.0.0.1:<port>/health` every 0.5 s until 200 (max 120 s) while checking the process is still alive, yields `{"pid": int, "load_seconds": float}`, and on exit (also on exception) terminates, waits 10 s, kills. Raises `RuntimeError` with the last 20 log lines if the process exits or health never turns 200.
- `peak_rss_mb(pid: int) -> float | None` — `VmHWM` from `/proc/<pid>/status`, in MB.

`tests/fake_llama_server.py`: stdlib HTTP server on the given `--port`; `/health` returns 503 for the first 0.5 s then 200; `--die` exits at once with a message; `/v1/chat/completions` returns a fixed reply with a `timings` object (used in Task 5).
